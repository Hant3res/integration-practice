# Архитектура интеграционного решения
## Система доставки еды

### Общая архитектура

Система построена на **микросервисной архитектуре** с **оркестрацией через Saga pattern**. Взаимодействие между сервисами осуществляется синхронно через REST API и асинхронно через вебхуки.

### Стиль интеграции

Выбран **гибридный стиль интеграции**:
- **Синхронные вызовы** — REST API между сервисами
- **Асинхронные уведомления** — вебхуки (при создании товара)
- **Оркестрация** — Saga pattern для транзакционности

### Паттерны

| Паттерн | Где используется |
|---------|------------------|
| **Saga** | Оркестрация заказа с компенсацией |
| **Circuit Breaker** | Защита при ошибках оплаты |
| **Retry** | Повторные попытки при временных ошибках |
| **Caching** | Кэширование каталога в Redis |
| **Webhook** | Синхронизация товаров между сервисами |

### Потоки данных

1. **Просмотр каталога** → Frontend → Catalog Service → Redis/DB
2. **Добавление в корзину** → Frontend → Cart Service
3. **Оформление заказа** → Frontend → Saga Orchestrator → Cart → Catalog → Payment → Orders
4. **Синхронизация товаров** → Catalog Service → Webhook → Orders Service
